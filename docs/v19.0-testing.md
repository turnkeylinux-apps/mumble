# Mumble 19.0 testing

## Scope and source decision

Mumble 19.0 uses Debian 13 Trixie packages for Mumble Server, Apache, PHP,
the ZeroC Ice PHP binding and supporting libraries. Trixie supplies the full
appliance stack, so no upstream repository or downloaded application artifact
is required. Webmin and its Apache and PHP modules continue to come from the
signed TurnKey Trixie repository.

Debian's Mumble 1.5 package renamed the executable from `murmurd` to
`mumble-server` and moved its configuration from `/etc/mumble-server.ini` to
`/etc/mumble/mumble-server.ini`. The v19 first-boot hooks use the new binary and
path for the SuperUser password and Ice write secret.

The Ice RPC endpoint carries a plaintext administration secret, so v19 binds
it to loopback and does not open port 6502 in the appliance firewall. Remote
Ice tools can connect through an SSH tunnel. Mumble client administration uses
the encrypted protocol on TCP port 64738.

The acceptance command is:

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance mumble \
    --source /home/agent/.local/worktrees/turnkey-apps/mumble/wish-mumble-v19-trixie
```

It builds a Trixie root filesystem in TKLDev, imports the configured root into
Docker, starts the normal systemd init path with first-boot credentials, and
runs `tests/v19.sh`. The retained report under
`~/.local/state/turnkey-v19-harness/runs/mumble/` records the exact source and
harness commits, archive and tree hashes, installed versions, configured-root
mode, application evidence, updater evidence, cleanup result, and verdict.

The claim that one Mumble daemon supports multiple virtual servers describes
an upstream capability. Acceptance tests the preconfigured default virtual
server rather than creating additional persistent instances.

## Updater check

`tests/v19.sh` runs `apt-get update` and checks eligible candidates for
`mumble-server`, `apache2` and `php-zeroc-ice` with `apt-cache policy`. It
records the versions before the refresh and proves they are unchanged
afterward. A pass means APT accepted the signed Debian and TurnKey Trixie
metadata, each identity-defining package has an eligible candidate, and no
Bookworm source remains configured.

## Known limitation

The Docker acceptance path does not exercise the installer, kernel, bootloader,
physical hardware or real-time multi-client audio quality. Mumble adds no
installer behavior, while its TCP control, TLS authentication and UDP listener
are exercised directly. The validated Core 19 baseline supplies the inherited
platform evidence.

## Deferred issues

The legacy `murmurdautofirewall` helper still searches process listings for the
old `murmurd` name when managing ports for additional virtual servers. The
documented default TCP and UDP port 64738 is opened independently and is tested
here. Updating dynamic rules for optional additional instances is deferred
until after the default server flow is accepted.
